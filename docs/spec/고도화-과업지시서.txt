Ⅰ. 사업 개요
1. 사업명
	•	전북지역 졸업생 취업지원 플랫폼 고도화(2차) 구축
2. 사업기간
	•	계약일로부터 91일 (13주, 약 3개월)
3. 사업내용
	•	전북지역 다수 학교의 재학생·졸업생·교사·협력기업을 연계하는 기존 취업지원 웹 플랫폼(1차)을 기반으로, 멀티스쿨·권한관리, 이력서·상담 문서화, 알림(SMS/알림톡 — 학교 유료 발송 계정 등록 시 진행), 워크넷 연동(학교 발급 인증키 제공 기반), 취업·견학·커뮤니티, 취업 추천 기능을 고도화 구축
4. 사업금액
	•	금 ○○○,○○○,○○○ 원 (VAT 포함)  
Ⅱ. 추진 배경 및 목적
1. 추진 배경
	•	단일 학교 한계: 1차 시스템은 단일 학교를 전제로 구축되어 전북지역 다수 학교·학교별 데이터 분리 미지원
	•	문서 산출 부재: 이력서·상담기록을 시스템에서 문서(PDF/Word)로 생성·보관 불가
	•	실시간 알림 부재: 상담·채용·지원 결과 등 즉시성 있는 알림 전달 수단 부재
	•	채용정보 수동 등록: 외부(워크넷) 채용정보를 담당자가 수기 등록하는 비효율
	•	맞춤 추천 부재: 학생 개인에게 맞는 채용공고를 찾아주는 추천 기능 부재
	•	데이터 신뢰성: 화면 데이터 일부가 브라우저 로컬(LocalStorage)에 의존하여 다중 학교·다중 사용자 공유·영속성 한계
2. 사업 목적
	•	전북지역 다수 학교와 소속 교사·학생을 하나의 플랫폼에서 운영하되 학교별 데이터 분리
	•	역할·소속 학교 범위·메뉴 단위까지 접근 권한을 통제하는 권한 관리 체계 적용
	•	이력서·상담 문서 자동화, 실시간 알림, 워크넷 연동으로 취업지원 업무 디지털화·자동화
	•	채용공고–학생이력 연관성 분석 기반 맞춤 취업 추천으로 매칭 효율 제고
	•	서버·DB 기반 전환으로 안정적 다중 학교·다중 사용자 서비스 기반 확보
	•	PC 및 모바일 반응형 웹, 보안 및 개인정보보호 준수

1.2 학생 이력서 관리 (PDF 문서 생성)
	•	단계형 이력서 작성(기본정보·학력·경력·자격증·수상·어학/스킬·자기소개서)
	•	복수 이력서·대표 이력서 지정, 임시저장·버전 관리
	•	템플릿 선택·실시간 미리보기, 한글 폰트가 임베드된 PDF 생성·다운로드
	•	생성 이력서 보관 및 취업 공고 지원 시 첨부 연계
1.3 교사 상담 이력 관리 (PDF·Word 문서 생성)
	•	상담 일지 작성(상담일자·유형(진학/취업/생활/심리)·내용·조치사항·후속 일정)
	•	학생별 상담 이력 타임라인 조회·검색, 후속상담 알림 연계
	•	상담확인서/상담일지 양식 PDF·DOCX 문서 생성·다운로드
	•	상담 유형·건수·기간별 통계 / 상담기록은 담당교사·해당 학교 관리자만 열람(민감정보)
1.4 SMS·알림톡 발송 서비스  (조건부 — 학교 유료 발송 계정 등록 시 진행)
	•	[진행 조건] 본 기능은 학교측에서 SMS/알림톡 유료 발송 계정(카카오 채널·비즈니스 인증·발송대행 계약·발신번호·발송비용)을 등록·제공하는 경우에 한해 구축하며, 미등록 시 해당 기능(SMS·알림톡 발송)은 과업 범위에서 제외한다.
	•	이벤트 기반 자동 발송(가입 완료, 상담 예약·리마인드, 채용 추천·마감 임박, 지원 결과, 견학 안내) 및 관리자 수동 발송
	•	템플릿·발송 이력·결과·비용 관리, 채널별 수신 동의 관리(정보통신망법 준수)
	•	알림톡 발송 실패 시 SMS/LMS 자동 대체발송(Fallback)
1.5 선배 취업 커뮤니티
	•	게시판 분류(취업후기/면접후기/직무 Q&A/멘토링) 및 카테고리·태그(직무·기업)
	•	글/댓글, 좋아요, 스크랩(북마크), 익명 작성, 첨부파일
	•	검색·인기글(베스트), 신고 접수 및 운영자 블라인드(모더레이션)
1.6 워크넷(고용24) API 연동
	•	[제공 조건] 워크넷(고용24) OpenAPI 인증키는 학교측에서 공공데이터포털을 통해 신청·발급받아 제공하며, 수급처는 제공받은 인증키로 연동을 개발한다.
	•	워크넷 채용정보·채용행사 API 주기 자동 수집(지역·직종 필터, 중복·만료 처리)
	•	통합 채용목록에서 자체 공고/워크넷 공고 구분 표시, 상세는 워크넷 원문 링크 연결
	•	수집 로그·동기화 상태 관리 및 관리자 수동 동기화
1.7 취업 공고 및 지원 관리
	•	공고 등록/관리(자체 공고) 및 워크넷 공고 통합 노출
	•	지원 워크플로우(접수 → 서류검토 → 면접 → 합격/불합격), 상태 변경 시 알림톡 자동 발송
	•	이력서(PDF) 첨부 연계, 학생별 지원 현황 추적, 취업률·지원 현황 통계 대시보드
1.8 취업 추천 서비스 (채용공고–이력 연관성 분석)
	•	콘텐츠 기반 매칭: 이력·공고 속성(직종·자격·스킬·지역·학력/경력) 가중 매칭 + 텍스트 TF-IDF/코사인 유사도
	•	연관규칙·협업 신호: 지원·스크랩 이력 기반 ‘함께 지원·관심 공고’ 연관 추천(장바구니 분석류)
	•	규칙 보정: 지역 우선·마감 임박·학과 적합도·신규 공고 가중으로 최종 점수 보정
	•	학생별 맞춤 공고 추천(점수순)·추천 사유 제시, 이력 변경·신규 공고 수집 시 재계산
	•	추천 노출·클릭·지원 피드백 수집(향후 학습형 고도화 기반), 1차는 설명가능형으로 구현
1.9 견학 공고 및 신청자 관리
	•	견학 공고 등록(대상 기업·장소·일자·정원·마감일·안내사항)
	•	정원/마감 관리(선착순 또는 승인제), 신청·승인·반려·취소 처리
	•	신청 확인·안내 알림톡 발송, 참가자 명단·출결 관리, 사후 보고
1.10 공통 기반 고도화
	•	데이터 영속화: LocalStorage 의존 로직을 서버 API·PostgreSQL 기반으로 전환
	•	멀티스쿨·권한: school_id 데이터 분리, 역할×학교범위×메뉴 권한 정책 엔진 및 공통 인가 가드
	•	파일 스토리지: 생성 문서·첨부 저장, DB에는 메타데이터만
	•	공통 모듈: 문서생성(PDF/DOCX)·알림·추천 모듈, 배치 스케줄러(node-cron)
	•	로깅·감사·백업: 개인정보 접근·권한변경 감사로그, 운영 로깅, 정기 백업

3. 보안 및 개인정보보호
3.1 암호화
	•	전송 중: HTTPS(SSL/TLS) 강제
	•	저장 시: 비밀번호 단방향 해시(Bcrypt), 개인정보(전화·이메일) 양방향 암호화(AES-256), DB 디스크 암호화(TDE)
3.2 접근 제어 및 권한
	•	역할×학교범위×메뉴 기반 접근 제어(RBAC + 메뉴 권한)
	•	학교 간 데이터 격리: 모든 조회에 소속 학교 범위 강제(공통 인가 가드), 타 학교 데이터 접근 차단
	•	상담기록 등 민감정보는 담당교사·해당 학교 관리자만 열람
	•	세션 관리(자동 로그아웃), 관리자·권한변경 활동 로그 기록
3.3 데이터 백업
	•	자동 백업(매일 1회), 시점 복구(최근 7일), 논리 백업(주 1회 암호화 저장)
3.4 법적 준수
	•	개인정보보호법·정보통신망법 준수, 14세 미만 법정대리인 동의
	•	개인정보 처리방침 게시, 장기 미접속 개인정보 파기, 메시지 수신동의 관리
4. 데이터베이스 설계
기존 스키마를 계승하고 멀티스쿨·권한·추천 포함 신규 테이블을 추가한다. 모든 업무 테이블에 school_id를 부여하여 학교 단위 데이터를 분리하며, 상세 컬럼·인덱스·ERD는 설계 단계 산출물로 제출한다.
주요 신규/확장 테이블
	•	학교·권한: schools, departments, roles, menus, role_menu_permissions, user_roles, users(+school_id)
	•	이력서·상담: resumes, resume_items, resume_documents, counseling_records, counseling_documents
	•	메시지·커뮤니티: message_templates, message_logs, message_consents, boards, post_categories, post_scraps, post_reports
	•	채용·워크넷·추천: jobs(확장), job_applications(확장), worknet_jobs, worknet_events, worknet_sync_logs, resume_keywords, job_keywords, job_recommendations, recommendation_feedback
	•	견학·공통: field_trips, field_trip_applications, files, audit_logs, notifications(확장)

Ⅴ. 과업의 준수사항 및 용역 계약
1. 계약의 목적
	•	본 계약은 학교의 의뢰에 의해 수급처가 당해 웹 플랫폼을 고도화 구축하는 데 따른 제반 사항을 규정하는 데 있음. 계약 작성 후 필요한 작업 변경이 있을 경우 쌍방의 서면 합의 후 수정 가능.
2. 웹 플랫폼
	•	본 계약에서의 웹 플랫폼이란 인터넷상에 학교의 취업 지원 관련 내용을 HTML 등 프로그래밍 언어로 종합 구성해 표현한 것을 말함.
3. 저작권
	•	본 계약에 의하여 수급처가 제작 완료한 당해 웹 플랫폼의 저작권은 학교에게 있음.
4. 웹 플랫폼 제작
4.1 자료의 제공
	•	학교는 제작에 사용될 내용(양식·기준·기존 데이터 등)을 수급처에게 제공
	•	학교 제공(워크넷): 워크넷(고용24) OpenAPI 인증키(공공데이터포털 발급)를 학교가 등록·제공하며, 미제공 시 워크넷 연동 기능은 진행 불가
	•	학교 제공(메시지, 선택): SMS/알림톡 유료 발송 계정(카카오 채널·발송대행·발신번호·발송비용)을 학교가 등록·제공하며, 미등록 시 SMS/알림톡 발송 기능은 과업에서 제외
	•	제작 기간의 착수 시점은 계약 체결일로부터 시작
	•	작업 순서: 요구사항 컨펌 → 설계 컨펌 → 개발 컨펌 → 검수 컨펌
	•	각 단계 컨펌 완료 후 다음 작업 진행
4.2 웹 호환성
	•	웹 플랫폼은 Google Chrome, Safari, Edge 및 PC·모바일 반응형 환경에 최적화
4.3 제작 완료 확인
	•	수급처가 인도한 플랫폼을 학교가 검수하였을 때 제작 완료로 인정
4.4 납품
	•	수급처는 제작 완료된 플랫폼을 인터넷에 게시 및 학교가 검수하게 함
5. 검수 방법 및 하자 보수
5.1 검수
	•	수급처는 제작 완료 시 학교에 즉시 통보
	•	학교는 인수일로부터 1주 이내에 검수 결과를 수급처에 서면 통보
	•	하자 발견 시 수급처가 보수
5.2 하자의 범위 (무상하자보수 기간 1년)
	•	서버 운영상의 오류(악성코드 무상 보수)
	•	게시판 및 프로그램 오류, 오타 및 링크 오류, 기타 기능상 오류
5.3 유지보수
	•	별도 계약 필요하며 기간은 협의
6. 인프라 및 호스팅
6.1 호스팅/인프라
	•	웹사이트 공개를 위한 서버 공간(학교 제공 또는 클라우드(AWS 등)) 및 운영 환경 제공
	•	SSL 인증서를 통한 데이터 암호화 보안 통신 보장
6.2 SSL 인증서 (선택)
	•	SSL 인증서 설치·연장 비용은 협의 후 별도 산정
6.3 면책 사항
	•	대량 트래픽 발생 사이트는 수급처가 호스팅 거부 가능
	•	바이러스 침투 또는 물리적 손상에 대한 손해는 수급처 책임 없음
7. 비밀유지
	•	계약 관련 상대방의 기술상·업무상 비밀 보장, 상대방 서면 동의 없이 제3자 누설 금지(계약 해제·해지 후에도 유효)
8. 업무 진행방법
	•	모든 문서에 대해 상호 확인 절차(confirm) 진행
	•	학교는 정해진 업무 내용에 대해 수정 및 보완 요청 가능
	•	개발 범위 외 또는 재수정은 추가 비용 산정 후 협의
	•	이미지 구입은 유료 청구(이미지투데이 제외)
9. 용역 수행 부수의무
9.1 개발 방법론
	•	수급처는 소프트웨어 개발 방법론을 학교에 제시하고 성실히 준수
9.2 결과물 제출
	•	용역 완료 후 학교에 다음 데이터 제출:
	•	소스 코드
	•	데이터베이스 스키마 및 ERD
	•	API 명세서
	•	관리자·사용자 매뉴얼
	•	배포·운영 가이드
9.3 콘텐츠 등록
	•	자료 등록 폼 스타일은 수급처 제공, 실제 등록은 학교가 관리자 화면을 통해 직접 진행
10. 납기
	•	제작 완료 납품 기한: 계약일로부터 91일 이내
	•	학교 사정에 의한 원고/컨펌 지연 시 수급처 책임 없음
11. 계약의 해지
11.1 학교의 해지 요구
	•	다음 각 호의 경우 60일 기간을 두어 시정 요구 후 불이행 시 해지 가능:
	•	학교의 시정 요구를 정당한 사유 없이 불이행
	•	수급처가 정상 경영 불가능 상태
	•	수급처가 파산·해산·청산·회사 정리 절차 진입
11.2 수급처의 해지 요구
	•	학교의 협정 위반에 대한 시정 요구를 학교가 정당 사유 없이 불이행 시
11.3 해지 효력
	•	서면 해지 통보 발송일로부터 발생
12. 불가항력
	•	전쟁·폭동·홍수·지진·정부 조치 등 불가항력적 사고로 인한 계약 불이행 또는 지체는 어느 일방도 책임 없음
13. 계약의 해석 및 재판관할
	•	계약에 명시되지 않은 내용 및 해석상 이의가 있을 경우 쌍방 합의로 수정·첨삭
